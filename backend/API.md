# API surface

All routes use `/api/v1`. Authenticated routes require an access token; monetary writes must be idempotent and update durable ledger records transactionally.

| Area | Routes | Status |
|---|---|---|
| Auth/session | `POST /auth/register`, `/auth/verify-otp`, `/auth/login`, `/auth/refresh`, `/auth/logout` | Implemented with Argon2id, one-time email OTP, rotating persisted refresh sessions, and session-bound access tokens |
| Profile | `GET /me`, `POST /users/switch-rider-mode` | Implemented; switch requires both approvals and no active job |
| Parks/trips | `GET /parks`, `/parks/summary`, `/trips`, `/trips/:tripID/seats`, `POST /trips`, `/trips/:id/capacity`, `/trips/:tripID/{depart,arrive,cancel}`, `/my-trips`, `/my-tickets` | State-name/code filtering, optional PostGIS radius sort, approved-bus trip creation, 120-second capacity lock, per-dispatch wallet fee, lifecycle controls, and operator cancellation refunds |
| Cloudinary | `POST /media/cloudinary-sign`, `/media/cloudinary-confirm`, `GET /media/:id/access` | Signed authenticated uploads, server verification, compressed incoming transformations, attachment access for conversation participants; confirmed KYC retained indefinitely, other uploads expire after 30 days, unconfirmed upload reservations expire after 24 hours |
| KYC | `POST /vehicle-registrations`, `GET /admin/kyc/queue`, `POST /admin/kyc/:registrationID/review` | Vehicle submission, ownership-checked assets, reviews, role approval and notifications implemented |
| VTU data | `GET /data/plans`, `POST /data/purchase`, `GET /data/orders` | Provider plans refresh into Neon with a 15-minute cache; wallet purchase is idempotent, debits/credits durable ledger entries, signs fulfilled receipts and retries ambiguous provider calls with the same reference |
| Amebo | `POST /amebo/chat`, `POST /amebo/tokens/buy` | Text prompts use daily free tokens before purchased rollover tokens; wallet pack purchases are idempotent; provider failures restore the debited token |
| Bike and parcel jobs | `POST /ride-orders`, `/parcel-orders`, `GET /rider/jobs`, `POST /rider/jobs/:kind/:id/{accept,start,complete}` | Wallet-paid orders, rider assignment, state transitions, parcel receiver OTP, ledger and signed receipts, rank advancement and one-time rank prizes |
| Wallet funding and ticket checkout | `POST /wallet/fund`, `POST /tickets/checkout`, `GET /payments/verify`, `POST /webhooks/paystack` | Paystack initialization and provider verification before settlement; verified ticket bookings and wallet funding write durable ledger entries and signed receipts. Ticket checkout also supports wallet payment; pending Paystack seat holds expire after 30 minutes |
| Boarding | `GET /keys/public`, `POST /tickets/scan` | Rotatable public key endpoint and atomic one-time QR/manual ticket scan; signed QR passes can be verified offline by the driver PWA and queued for sync while the PWA remains open |
| Account activity | `GET /wallet/transactions`, `/transactions`, `/transactions/:id/receipt`, `/notifications`; `PATCH /notifications/:id/read`, `POST /notifications/read-all` | Read APIs implemented; signed receipts exist for verified wallet funding, wallet ticket purchases/refunds, and paid subscriptions. The transaction feed exposes all ledger categories and signed receipts |
| Push | `POST/DELETE /push-subscriptions/:id` (POST path omits `:id`) | VAPID Web Push subscription and wallet/KYC event delivery implemented |
| Support/disputes | `GET/POST /support/cases`, `GET/POST /support/cases/:caseID/messages`, `POST /disputes` | Customer case creation, correspondence, and dispute filing implemented |
| Admin support/disputes | `GET /admin/support/cases`, `POST /admin/support/cases/:caseID/messages`, `PATCH /admin/support/cases/:caseID`, `GET /admin/disputes`, `POST /admin/disputes/:disputeID/resolve` | Admin case queue, public replies/private notes, priority/status changes, and auditable dispute decisions implemented; decisions do not move funds or start provider refunds |
| Realtime | `POST /ws-ticket`, `GET /ws?ticket=...`, `GET /trips/:tripID/messages`, `GET /admin/live-trips` | Authenticated trip chat, Cloudinary image attachments, six-minute purge, SOS context preservation, opt-in foreground GPS, source priority, and admin live-trip feed |

**Implemented with limits:** Ticket checkout supports Paystack or DE RIDE wallet payments; ticket refunds currently credit the DE RIDE wallet only. Wallet checkout does not add a Paystack processing fee. Subscription upgrades debit the wallet and downgrades to an eligible free plan take effect immediately; upgrades do not yet use recurring Paystack billing. VTU purchases currently support wallet payment only and require an upstream implementing the documented adapter contract. Admins can reply to support cases, record private notes and resolve filed disputes; dispute decisions do not move funds or initiate provider refunds.

**Not yet implemented:** Original-funding ticket refunds; Paystack-backed subscription billing, VTU, rider jobs and Amebo token packs; Amebo voice requests; escrow and automatic dispute settlements; background sync after the scanner page closes; dedicated hardware GPS webhook ingestion; navigation and Directions API; multi-bay operator queue controls; full ticket QR rendering/offline ticket vault; rank rewards for passenger bus completions; cancellation/refund workflows for bike and parcel orders. Amebo text chat and wallet rollover token packs are implemented.

The VTU adapter contract is `GET {VTU_BASE_URL}/data/plans` returning `{"status":true,"data":[{"code":"...","network":"MTN|AIRTEL|GLO|9MOBILE","allowance":"...","price_ngn":1000}]}` and `POST {VTU_BASE_URL}/data/purchase` with `network`, `plan_code`, `phone`, and stable `reference`; a successful response must echo that reference at `data.reference`. Explicit provider rejection triggers a wallet reversal. Timeouts and ambiguous responses remain PROCESSING and are retried up to five times with the same reference; unresolved orders require provider reconciliation. Configure the upstream to treat that reference as an idempotency key.

For media uploads, configure a signed Cloudinary upload preset with strict 5 MB limits, supported formats, authenticated delivery, and incoming transformation policies. Image incoming transformations apply before storage; PDF documents are size-validated but remain their original file format. KYC assets have no automatic expiry; non-KYC media is removed by the hourly worker after 30 days.

For payments, configure `PAYSTACK_SECRET_KEY`, webhook signing secrets, `QR_PRIVATE_KEY_PEM`, and `QR_KEY_ID`. The webhook handler authenticates the raw request body, records the event, acknowledges it, and uses a retryable worker; the worker verifies each transaction with Paystack before crediting the wallet or confirming a ticket. Never trust a browser callback as proof of payment.

The process-local WebSocket hub and in-memory cooldown/cache are per instance. Run a single API instance until shared realtime/cache infrastructure is intentionally introduced. Financial and KYC records remain durable in Neon Postgres.
